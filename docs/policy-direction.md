# 이 검증 자료가 InfraMorph에서 맡는 역할

InfraMorph의 목표는 범용 공격 탐지기가 아니라 **코드에서 배포 요구를 이해하고,
환경별 계획·코드 변경으로 옮기되 근거 없는 판단과 허용되지 않은 변경을 실행 전에 막는 것**입니다.
따라서 공격 입력만 많이 모으는 것보다 정상 분석·변환이 통과하고 잘못된 판단이 멈추는지를
같은 기준으로 검증해야 합니다.

## 요구사항과 검증 위치

| 설계의 요구 | 이 PR의 입력 | 실제 검증 책임 | 현재 확인 가능한 범위 |
|---|---|---|---|
| 저장소 문구는 명령이 아니라 데이터 | README·주석 인젝션 3개 + 정상 대조군 | C의 Agent 도구 제한·분석 | 공격 문구와 원본 근거가 보존되는지 |
| AI의 판단에 코드 근거 필요 | 정상 Intent, 없는 파일·줄번호·경로 이탈 | E Intent Gate (5) | fixture 근거 위치와 위반 한 가지의 존재 |
| 공개 web 1개, worker 비공개 | 공개 web 중복·worker 공개 | B 스키마 + E Intent Gate | 사례가 합의된 MVP 제한을 위반하는지 |
| Node 22 MVP 지원 범위 | 미지원 runtime Intent | B 스키마 + E Intent Gate | 정상/위반 입력의 차이 |
| 저장·DB 전환만 허용 | 정상 저장 호출·provider 변경·신규 파일 | C 패치 + E Patch Gate (8) | 정상 대조군의 문법·경로·diff 유효성 |
| 허용되지 않은 변경은 빌드 전 차단 | 범위 밖 수정·삭제·이름 변경, 금지 코드·문법 오류·symlink 변환 | E Patch Gate → Builder | 위험 변경이 fixture 안에 실제로 존재하는지 |
| 원본·호스트 경계 보존 | ../, 절대 경로, 외부 symlink, 정상 내부 경로 | B snapshot + C 도구 + E 패치 경계 | 임시 디렉터리에서 경로가 의도한 대상을 가리키는지 |
| 모든 결과는 추적 가능 | corpus commit, base SHA-256, 담당·기대 결과 | 각 모듈 + D 타임라인 | 입력 버전과 기대 결과의 재현 가능성 |

**CI의 자료 검증과 제품의 정책 판정은 다릅니다.** 제품 Gate를 이 저장소에 하나 더 만들어
맞춰보면 실제 제품과 다른 규칙으로 잘못된 확신을 줄 수 있습니다. 이 PR은 고정된 사례를
검사하며, 실제 판정은 inframorph 구현을 연결해 측정합니다.

## 잘못 차단하는 경우도 확인

정상 Prompt·Intent·저장 패치·DB 패치·신규 파일·내부 경로의 6개 대조군을 유지합니다.
악성 문구가 있는 저장소라도 Agent가 이를 무시하고 올바른 Intent를 반환하면 처리할 수 있습니다.
단순히 README에 공격 문장이 있다는 이유만으로 모든 배포를 거부하는 구현은 목표와 다릅니다.

신규 파일 허용 목록은 **자료 검증용 제안**입니다. 제품 패치 범위는 C·E가 확정해야 합니다.
Prisma provider 변경의 실제 기동 가능성과 DB 데이터 유지까지 현재 검사에서 주장하지 않습니다.

## Builder / AWS 전달 합의와의 연결

공유된 합의안의 책임은 E=검증된 artifact의 이미지 빌드, A=ECR push 이후입니다.
B가 제시한 `Plan.source_revision` / `BuildArtifact.source_revision`의 전체 SHA와
`image_tag` / `image`의 대응, AWS `linux/amd64`는 그대로 참조하며 여기서 재정의하지 않습니다.

다음 통합 단계에서는 Gate가 거부했을 때 Builder가 호출되지 않는지,
검사한 artifact와 실제 빌드 입력이 같은지 확인해야 합니다. 원본 source SHA만 같아도
그 후의 패치 내용은 달라질 수 있으므로 patched artifact 식별·불변성 연결은 C·E·B의
미완료 합의로 둡니다. Local/AWS 동일 태그가 서로 다른 패치본을 덮어쓰는 문제도
Builder 이슈에서 확인하며 이 PR에 임의 필드를 추가하지 않습니다.

주장을 의미적으로 입증한다는 보장과 다릅니다. 난독화 코드, 모든 언어의 취약점,
symlink 교체 경쟁 조건 같은 범용 보안 문제를 이 39개 사례로 해결했다고 주장하지 않습니다.
외부 예제 앱과 오탐·미지원 비율은 아직 측정하지 않았습니다.
