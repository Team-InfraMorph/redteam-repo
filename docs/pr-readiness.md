작성자의 기준별 자체 평가이며 GitHub 리뷰 승인을 대신하지 않습니다.

## 확인한 증거

- 전체 테스트 40개 통과: 기존 PR·이슈 정책 24개 + 검증 자료 관련 16개.
- 39개 사례를 직접 검사하는 `python3 scripts/check_fixtures.py` 통과.
- 모든 사례의 기대 결과를 뒤집으면 검사가 실패함.
- 각 인젝션 입력에서 공격 내용만 제거하면 검사가 실패함.
- 미신고 파일 추가·삭제·이름 변경, 정상 파일의 symlink 변환을 감지함.
- 새 JavaScript 파일의 문법 오류와 정상 대조군에 삽입된 eval을 감지함.
- 위반 Intent를 정상 입력으로 바꾸거나 정상 근거를 존재하지 않는 줄로 바꾸면 실패함.
- 이 저장소의 검사는 production Agent, B의 실제 schema validator, E Gate, Builder를 실행하지 않음.
- 최신 CI 결과는 PR의 repo-policy 검사에서 확인함. CI는 Node 22, 로컬 확인은 Node 26 환경임.
- 소비 저장소 교차 검증: inframorph `feat/e-policy-hardening`이 이 브랜치의 고정 SHA를 pin해
  39개 전부를 실제 E Gate와 C 호스트 경계로 실행했고 기대 판정·사유 코드가 일치함(실패 0, 미실행 0).
  근거는 inframorph `validation/e-policy-hardening-results.json`이며 해당 commit에서 재현 가능함.
- 1차 25개의 기대 결과는 변경하지 않고 14개를 추가함. 규칙별로 정상/위반 최소 차이 쌍을 둠.
  실제 모델 행동은 여전히 미측정이고 외부 예제 앱·오탐 비율도 측정하지 않음.

## 병합 후 별도 완료해야 할 것

[설계 대응표](policy-direction.md)의 통합 체크리스트와 연관 이슈를 계속 열어 둡니다.
source revision이 동일하다는 것만으로 패치 artifact까지 동일하다고 보장하지 않습니다.
Gate 거부 후 Builder 미호출, 실제 오류 사유·타임라인, secret 미노출은 제품 연결 후 확인합니다.
